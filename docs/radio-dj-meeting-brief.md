# 技術会議用：AI応援歌アプリ／ラジオDJ体験

更新日：2026-11-16

## いま動いている土台

- Next.js 16 / TypeScript。PC・ローカル利用が前提。
- DJとの通話画面、会話ログ、必須情報の充足判定、非同期の楽曲ジョブ、曲再生画面がある。
- デモモードでは外部APIを使わず、ローカル音源とモック結果を使える。
- 本番モードのコードにはOpenAI RealtimeとEleven Musicの接続口があるが、今回の作業では実行していない。
- mainには未統合。作業ブランチは `experiment/radio-dj-flow`。

## 目指す体験

```text
スタート
  → 生電話の呼び出し
  → DJとの会話
  → 必要情報がそろう
  → 会話を保ったまま楽曲準備
  → 待ち時間の雑談
  → 曲完成
  → DJが自然に紹介
  → 利用者操作で曲を聴く
  → 歌詞を見ながら聴く
  → DJの短い締め
```

## 必要な機能

| 機能 | 現状 | 会議で確認すること |
| --- | --- | --- |
| DJとの会話 | Realtime接続口あり／未実機検証 | 音声会話を必須にするか、文字・ターン制を許容するか |
| 情報充足判定 | 既存の必須4項目で暫定実装 | 正式に必要な情報、深掘り量、会話時間 |
| 楽曲設計 | OpenAI要約→90秒プロンプト | 本人固有の言葉・感情をどこまで必須にするか |
| 楽曲生成 | Eleven Musicジョブ実装済み | 実生成時間、失敗率、再試行、料金上限 |
| 待機会話 | 生成開始後の雑談指示あり | 曲に反映しないことをどう自然に伝えるか |
| 曲紹介 | 仮文言・UIあり | DJ音声で紹介するか、画面中心にするか |
| 再生・歌詞 | ローカル音源、歌詞キュー、終了検知あり | 実タイムスタンプ精度、再生終了後の導線 |
| DJ素材 | CSSの鳥型仮シルエット | 正式名称、素材、声、人格、権利確認 |

## 状態設計（採用候補）

```text
conversation
  → generating
  → songReady
  → transitioningToSong
  → readyToPlay
  → playing
  → finished

失敗時：error
```

- `generating`：曲に使う会話スナップショットを固定済み。以後の雑談は曲に反映しない。
- `songReady`：曲は届いたが、利用者・DJの発話を遮らない。
- `transitioningToSong`：次のDJ返答で直前の発話を受け止め、曲紹介へ締める。
- `readyToPlay`：DJの紹介終了後だけ「曲を聴く」を表示する。

## 技術上の課題

- Realtimeのニックネーム認識、字幕順序、声の人格表現は未検証。
- 楽曲ジョブはメモリ管理であり、開発サーバー再起動後に完全復元できない。
- 実音源の生成時間・タイムスタンプ精度・API障害時の実挙動が未確認。
- ブラウザの自動再生制限により、音源開始は利用者操作が必要。
- 既存のドメインテストには、DJ変更と無関係なモックプロンプト期待値の不整合が1件ある。

## 明日決めたいこと

1. 音声会話は必須か。失敗時の文字入力フォールバックは必要か。
2. 情報充足の正式条件は何か。4項目に加えるべき「本人らしい具体」は何か。
3. DJの正式名称・人格・声・正式素材を誰が用意するか。
4. 生成待機が何秒を超えたら案内／中止／再試行を出すか。
5. Eleven Musicの生成を何回まで許可するか。スタッフ向け復旧導線は必要か。
6. 再生終了後に感想を聞くか、すぐ次の来場者へ渡すか。

## 会議後の最短実装順

1. モックで上記状態遷移を最後まで通す。
2. OpenAI Realtimeを一度だけ接続して、会話・認識・字幕を評価する。
3. Eleven Musicを一度だけ生成して、待機時間・音源・歌詞タイムスタンプを確認する。
4. 実測値をもとに待機演出・再試行・スタッフ運用を決める。
